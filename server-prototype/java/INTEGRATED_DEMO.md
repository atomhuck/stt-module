# Локальное демо: интервью, STT, роли и подсказки

Два локальных Java-модуля этого репозитория работают вместе: `vosk-stt-demo` использует Vosk `vosk-model-ru-0.42` и анализирует ответы, а `server-prototype/java` добавляет Nemotron 3 + CAM++, роли и общую страницу интервью. Whisper является отдельным Python-процессом. Предварительная подсказка идёт через read-only `InterviewSession.peek`; она не фиксирует ответ и не меняет правила `DecisionPolicy` / `AnswerAnalyzer`.

## Поток аудио

- Эталон кандидата записывается автоматически 10 секунд из **того же смешанного сигнала**, что и интервью: `(микрофон + звук компьютера) / 2`. Во время эталона должен говорить только кандидат; другие голоса и воспроизведение TTS загрязнят эталон.
- Во время интервью браузер ресемплирует микрофон и звук всего экрана в один моно PCM 16 кГц поток по формуле `(микрофон + звук компьютера) / 2`. Vosk видит весь этот смешанный поток; источник звука не считается ролью.
- Браузер посылает кадры по 160 мс. Java передаёт их в одну Vosk-сессию и группирует по четыре в блоки по 640 мс для одной открытой сессии Nemotron. Поток CAM++ сравнивает скользящие окна с эталоном и голосовыми группами. Два совпадения выше 0,60 с отрывом от второго результата не менее 0,05 дают предварительную роль; итоговое назначение Nemotron/CAM++ может её исправить.
- Два последовательных CAM++ совпадения дают предварительную роль; накопленные 2,5 с чистой речи и согласующийся speaker ID подтверждают её. Только подтверждённые фрагменты кандидата передаются в stateful-механизм Артёма и Whisper. Read-only `peek` может получить собранный текст Vosk после двух предварительных совпадений и показывает причину, покрытие, число слов и, если применимо, текст уточнения. Он не принимает решение и не меняет состояние анализа.
- Если подтверждённая реплика долго ждала финальной разметки Nemotron, её кадры могут поступить в STT очередью. Буфер анализа кандидата теперь вмещает до 512 кадров по 160 мс (около 82 секунд). При экстремальном переполнении отбрасывается только новый кадр, интервью продолжается, а потеря фиксируется как `candidate_queue_overflow` и в `integration-summary.json`.
- TTS по умолчанию включён. Для каждого основного вопроса выбирается следующий доступный русский голос браузера; первый голос выбирается в списке на странице. Уточнение использует голос своего основного вопроса. Голоса берутся из `speechSynthesis` Chrome/Windows, поэтому число разных голосов зависит от установленных русских голосов; при нехватке они повторяются по кругу. Анализ ответа открывается после озвучки. После решения Артёма следующий TTS ждёт окно отмены. Если кандидат продолжил, решение отменяется и следующий вопрос не озвучивается. Для живого интервьюера выключите TTS; задайте вопрос вслух и нажмите «Вопрос задан».

Аудио от нескольких людей в одной системной дорожке не разделяется источником. При наложении речи спорные слова остаются «Не определено». Используйте наушники, чтобы TTS/звук удалённого звонка не попадал повторно в микрофон.

## Запуск на этом компьютере

### Подготовка

1. В IntelliJ откройте `server-prototype/java/pom.xml`. Подключите `vosk-stt-demo/pom.xml` из этого же репозитория через **File → Attach Project**.
2. Проверьте, что каталог `C:\Users\Public\NemotronTest\vosk-model-ru-0.42-native` содержит `README`, `am/final.mdl` и `graph/words.txt`, а в README указана версия 0.42. Не заменяйте эту модель малой.
3. Соберите `vosk-stt-demo`: из корня репозитория выполните `mvn -f vosk-stt-demo/pom.xml package -DskipTests`. Это создаёт JAR и не загружает модель Vosk во время сборки.
4. В Maven settings IntelliJ укажите локальный репозиторий `C:\Users\Public\NemotronTest\maven-repository`, если стандартный `.m2` на пути с кириллицей недоступен.
5. В IntelliJ выберите **Integrated demo (Vosk 0.42 + Whisper + Nemotron)** из `.run`. Main class — `ru.aireferent.diarization.DemoLauncher`, working directory — `server-prototype/java`, JRE — Java 17+. Прямой `Main integrated` запускает страницу без дочерних процессов Vosk и Whisper.

### Один запуск

1. Остановите старые процессы на портах 8080, 9000 и 8765.
2. Нажмите Run у общей конфигурации один раз. Launcher проверит модель именно версии 0.42, JAR, Python-окружение Whisper, файлы Nemotron/CAM++ и вопросы. Затем запустит Spring Boot/JAR Артёма с `VOSK_MODEL_PATH`, Whisper `small` / `int8` на CPU с двумя потоками, дождётся готовности обоих сервисов и стартует браузерный сервер. На этом компьютере первая загрузка 0.42 может занять около 2–3 минут; дождитесь сообщения `Vosk 0.42 и Whisper готовы`.
3. В Chrome или Edge откройте `http://localhost:8765`. Разрешите микрофон и демонстрацию **всего экрана со звуком**. Если браузер не дал системный звук, повторите выбор экрана.
4. Нажмите «Записать голос кандидата» и говорите около 10 секунд. Микрофон и системный звук уже сведены в один сигнал; через 10 секунд эталон автоматически завершится (или можно остановить запись кнопкой раньше). Во время эталона не должно звучать ничего, кроме голоса кандидата. После принятия эталона автоматически начнётся интервью и прозвучит первый вопрос.
5. Для отключения TTS снимите флажок до начала интервью. После каждого живого вопроса нажимайте «Вопрос задан»; это открывает анализ ответа. Список в поле «Первый голос» задаёт начальный голос; следующие основные вопросы чередуют доступные русские голоса, а уточнения сохраняют голос родительского вопроса.
6. В конце нажмите «Завершить интервью». Страница дождётся финального отчёта и покажет общую оценку, оценки по критериям и покрытие каждого вопроса. Если Whisper включён, сервис дождётся его уточнений (до настроенного тайм-аута), затем выдаст отчёт. Папка результатов появится в терминале и на странице под `C:\Users\Public\NemotronTest\integrated-runs`.

Одна кнопка в IntelliJ запускает launcher и оба сервиса. После изменения `vosk-stt-demo` заново соберите его JAR и запустите общую конфигурацию. Если порт занят, launcher сообщит его до запуска; закройте прежнее окно Run и повторите.

### Пути для другого участника

В Run Configuration → Environment variables задайте пути, отличающиеся от этой машины:

```text
ARTEM_PROJECT=D:\work\stt-module\vosk-stt-demo
NEMOTRON_HOME=D:\models\NemotronTest
VOSK_MODEL_PATH=D:\models\vosk-model-ru-0.42
WHISPER_PYTHON=D:\models\whisper-venv\Scripts\python.exe
WHISPER_MODEL=small
```

В `NEMOTRON_HOME` launcher ожидает `runtime/bin/nemo_speech_asr_c.dll`, `model.gguf`, `speaker_embedding_model.onnx`, `whisper-venv` (если не задан `WHISPER_PYTHON`) и `integrated-runs`. В каталоге `vosk-stt-demo` должны быть `target/vosk-stt-demo-1.0.0.jar`, `tools/whisper_server.py` и `demo/questions-six.tsv`. Сначала установите Whisper-зависимости командой `pip install -r vosk-stt-demo/tools/requirements-whisper.txt` из корня репозитория в отдельное Python-окружение и загрузите модель faster-whisper `small`. Launcher использует CPU, int8 и два потока.

### Если запуск не проходит

- **`Модель ... не подтверждает версию 0.42`** — выбран не тот каталог; проверьте `VOSK_MODEL_PATH/README`.
- **`Failed to create a model`** — JVM нашла каталог, но нативный Vosk не смог загрузить модель. Смотрите вывод `[Vosk]`; проверьте свободную память, структуру модели и путь.
- **`Не найдено ...`** — launcher напечатает конкретный отсутствующий файл. Исправьте путь или заново соберите JAR Артёма.
- **Whisper не поднялся** — проверьте `WHISPER_PYTHON`, `faster-whisper`, модель `small`, доступность порта 9000 и логи `[Whisper]`. Объединённый launcher намеренно останавливается с ошибкой, если Whisper не готов.
- **Сервис Артёма не подключается** — не запускайте вкладку отдельно; запускайте всю конфигурацию, которая должна поднять порты 8080 и 9000 до Java-страницы.

## Результаты и метрики

На каждое интервью создаются:

- `events.jsonl`, `segments.json`, `summary.json` — исходные файлы Nemotron/CAM++;
- `stt-events.jsonl` — единый поток Vosk с `source: "mixed"`, словами и временными метками;
- `timeline-events.jsonl` — роли, пересмотры слов, предварительные подсказки и отмены, решения Артёма, итоговый отчёт, TTS и Whisper;
- `timeline.json` — слово + начало/конец + роль + источник модели + предварительный/итоговый статус;
- `integration-summary.json` — p50/p95/max первого partial, роли, передачи подтверждённого кандидата, предварительной подсказки, решения, показа в браузере и Whisper.

Цель **p95 ≤ 3 секунды** относится к предварительной подсказке от конца ответа до появления на странице. Она считается достигнутой только после живого прогона. Итоговое решение, TTS и Whisper измеряются отдельно. Прежняя медиана показа подсказки была 11,14 секунды; эта реализация ещё должна быть проверена живым прогоном на том же оборудовании. Модели, аудиозаписи и папки прогонов остаются на компьютере; они не добавляются в Git.

## Проверки кода

Для обоих Java-модулей выполните тесты, сборку и Javadoc по [инструкции разработки](../../docs/development.md). Тест Vosk с настоящей моделью запускается только при заданном `VOSK_MODEL_PATH`; без модели он пропускается.

Живой прогон с четырьмя говорящими, наложением речи, TTS, Whisper и всеми JSON проверяется отдельно по [сценарию демо](../../vosk-stt-demo/demo/SCENARIO.md). Ни одна цифра целевой задержки не объявляется подтверждённой без этого прогона.
