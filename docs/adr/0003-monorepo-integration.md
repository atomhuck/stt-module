# ADR 0003 — Два Java-модуля в одном репозитории

**Статус:** принято.

**Контекст.** Диаризация и сервис интервью имеют разные зависимости и жизненные циклы: Nemotron/CAM++ запускаются в worker, Vosk и движок интервью — в Spring Boot. Раньше сборка общего демо требовала соседний checkout `vosk-stt-demo`, из-за чего документация и исполняемый код расходились.

**Решение.** Хранить Spring Boot проект в `vosk-stt-demo/` рядом с `server-prototype/java/`, сохранив отдельные `pom.xml`. Источник переноса — локальная рабочая версия [проекта Артёма](https://github.com/ArtemSorin/vosk-stt-demo) на основе коммита `a4bb022` с последними незакоммиченными изменениями. `DemoLauncher` по умолчанию ищет модуль внутри текущего репозитория; `ARTEM_PROJECT` остаётся явным переопределением. Обмен идёт через два WebSocket-канала. В `/ws/stt` уходит смешанный звук, в `/ws/interview` — только подтверждённая речь кандидата. Схемы HTTP и WebSocket поддерживаются отдельно.

**Следствия.** CI собирает и тестирует оба модуля. Общий запуск всё ещё требует локальных моделей и отдельного Python-окружения Whisper. Наличие кода в одном репозитории не делает Spring Boot API доступным только через loopback: его сетевую привязку определяет собственная конфигурация.
