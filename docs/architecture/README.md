# Архитектура прототипа

## Место для схемы сокомандника

**Схема архитектуры будет добавлена сокомандником.** Здесь нужна ссылка на подготовленный им исходник и изображение. Схема должна показывать браузер или микрофон, Java worker, Nemotron, CAM++, файлы результата, модуль `vosk-stt-demo` (Vosk и анализ интервью) и Whisper. Подпишите направления аудио, событий и результатов, порты 8765/8080/9000 и сетевые границы: сервер страницы слушает loopback, а адрес Spring Boot задаётся конфигурацией. Перед вставкой сверить схему с текущим кодом и [ADR](../adr/README.md).

В каталоге уже есть `c4-current-system.svg` и `c4-current-system.png`. Они сохранены отдельно и не подменяют схему, ожидаемую от сокомандника.

## Компоненты и поток

1. `Main` выбирает режим. `browser` и `integrated` запускают `BrowserMode` с HTTP-сервером на `127.0.0.1:8765`; `live` читает микрофон, `stream` — готовый WAV, `verify` проверяет готовые сегменты.
2. Во время интервью браузер сводит микрофон и системный звук в один моно PCM16 16 кГц поток. `integrated` отправляет кадры по 160 мс, базовый `browser` — до 640 мс. `BrowserMode` группирует четыре входных кадра перед `LiveSession`: обычно 640 мс в `integrated` и до 2,56 с в `browser`. `NemotronStream` держит одну нативную сессию на интервью.
3. Nemotron возвращает интервалы и временные speaker ID. `OnlineRoles` сравнивает эмбеддинги CAM++ с эталоном кандидата и группами интервьюеров. Короткие или неоднозначные фрагменты остаются «Не определено»; `ConfidenceScore` даёт эвристическую оценку отображения.
4. `LiveSession` владеет решениями о ролях и базовыми `events.jsonl`, `segments.json`, `summary.json`. В `integrated` `IntegrationBridge` также передаёт смешанный поток в Vosk и подтверждённые фрагменты кандидата в анализ интервью сервиса Артёма; предварительная подсказка `peek` не фиксирует ответ. Whisper даёт уточнение после основного потока.

`IntegrationBridge` — WebSocket-клиент второго Java-модуля этого репозитория, `vosk-stt-demo`. Он подключается к `/ws/stt` и `/ws/interview` на порту 8080. Vosk создаёт текст и временные метки, `EndpointDetector` определяет конец ответа, `InterviewSession` и `DecisionPolicy` принимают решение, а `InterviewExcelReport` собирает XLSX. Python-сервис Whisper подключается к Spring Boot по локальному HTTP после основного решения. [Карта контрактов](../api/README.md) разделяет HTTP и WebSocket; [OpenAPI BrowserMode](../api/openapi.yaml) охватывает только порт 8765.

## Ограничения

- На один активный браузерный сеанс приходится одна пара моделей и один worker; одновременные интервью сервер не обслуживает.
- Локальный HTTP-сервер не содержит полноценной авторизации и не предназначен для публикации в сети. `X-Session-Id` лишь связывает запросы с текущим интервью.
- Переполнение очереди аудио останавливает текущую запись; уже принятые чанки обрабатываются и сохраняются. Перекрывающуюся речь в одном аудиосигнале нельзя надёжно разделить по источнику.
- Модели, нативные библиотеки, аудио и результаты не хранятся в Git; для повторяемого прогона фиксируйте их версии и параметры отдельно.
- Отдельный Spring Boot сервис по умолчанию слушает порт 8080 согласно `application.yml`; он не наследует loopback-ограничение `BrowserMode`. Скачиваемый XLSX может включать эталонные ответы; `interview.report-download=false` выключает выдачу файла.
