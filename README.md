# STT module: серверный прототип диаризации

**Java-версия для запуска в IntelliJ IDEA:** [server-prototype/java/README.md](server-prototype/java/README.md). Она переносит потоковый прогон и файловую проверку ролей с сохранением JSON/JSONL/CSV. Python-скрипты ниже оставлены как воспроизводимый исходный вариант и для сравнения результатов.

Черновик для обработки интервью на сервере. Модель и аудио не загружаются на компьютер интервьюера. Веб-приложение должно передать запись серверному backend, а backend — запустить этот worker и вернуть JSON/CSV с временными интервалами и ролями говорящих.

Сейчас в репозитории только CLI-worker для проверки файлов. HTTP API, загрузка из браузера, авторизация и интеграция с основным приложением ещё не реализованы.

## Что делает прототип

1. NVIDIA Nemotron 3 Diarization определяет речевые интервалы и предварительные ID говорящих.
2. Отдельная модель 3D-Speaker извлекает голосовые эмбеддинги.
3. Интервалы сравниваются с эталоном кандидата. Остальные группы получают подписи «Интервьюер 1», «Интервьюер 2» и т. д. Каждому речевому сегменту автоматически назначается роль. Для коротких и спорных отрезков скрипт использует устойчивую роль исходного speaker ID или ближайшую реплику и отмечает низкую уверенность.

Для воспроизведения теста эталон задаётся интервалом **20–30 секунд** аудиофайла. Это значение относится к тестовому фрагменту. В продукте эталон следует получать из отдельной записи, которую интервьюер включает и выключает во время чистой речи кандидата.

## Размещение на сервере

Нужны Python 3.12+, `nemo-speech` для целевой ОС и две заранее размещённые на сервере модели:

- GGUF-файл `nvidia/Nemotron-3-Diarization`;
- ONNX-файл `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`.

Файлы весов и аудиозаписи в Git не добавляются. Скрипт проверяет наличие локальных файлов моделей и прекращает работу, если их нет; во время анализа ничего не скачивает. Разместите модели на сервере в соответствии с внутренними правилами доступа и хранения. Перед коммерческим развёртыванием отдельно проверьте лицензии именно тех файлов весов, которые выбраны.

Установите зависимости в окружении backend:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r server-prototype/requirements.txt
```

Передайте на сервер тестовый WAV: несжатый PCM, 16 кГц, 16 бит, mono. Затем запустите worker, подставив локальные пути сервера:

```bash
python server-prototype/verify_candidate.py \
  --audio /srv/stt/input/interview.wav \
  --nemo-exe /usr/local/bin/nemo-speech \
  --nemo-model /srv/stt/models/Nemotron-3-Diarization.q8_0.gguf \
  --model /srv/stt/models/3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx \
  --enroll-start 20 \
  --enroll-duration 10 \
  --output /srv/stt/output/interview.verified.json \
  --csv /srv/stt/output/interview.verified.csv
```

Если Nemotron уже запущена и есть JSON с сегментами, вместо `--nemo-exe` и `--nemo-model` передайте `--diarization-json /path/to/diarization.json`.

По умолчанию эталонная WAV-запись отдельно не сохраняется. Параметр `--reference-wav` включает её сохранение только для отладки. Временная рабочая копия для Nemotron удаляется после обработки. Backend всё равно должен удалить исходный загруженный файл и выходные артефакты в соответствии с настройками хранения проекта.

## Результат и ограничения

JSON и CSV содержат интервалы, метки ролей, сходство с эталоном, уверенность и основание автоматического решения. Числа сходства — это оценки модели, не проценты вероятности. Низкая уверенность не создаёт задачи человеку: скрипт всё равно возвращает роль.

На CPU ноутбука AMD Ryzen 5 5600H полный повторный прогон тестового 125-секундного русского фрагмента занял 47,43 секунды. Для интервала эталона 20–30 секунд получилось 13 речевых сегментов «Кандидат» и 8 сегментов «Интервьюер 1»; эталонный интервал учтён отдельно как «Кандидат (эталон)». Семь сегментов имеют низкую уверенность, но все получили роль автоматически. Это демонстрационный результат на одном интервью, а не измерение точности на русском языке. Пороги 0,60 для кандидата и группировки интервьюеров остаются стартовыми настройками; до применения в продукте их нужно проверить на размеченных записях проекта.

Worker принимает файл и запускается как CLI. Для продукта нужен серверный endpoint, который принимает аудио и отдельную запись эталона, вызывает worker, возвращает результат и удаляет временные файлы. Этот endpoint должен также проверять формат, размер и длительность аудио и ограничивать доступ к результатам.

## Воспроизведение потока из файла

`server-prototype/stream_replay.py` проверяет **потоковый режим** на готовом WAV. Он открывает одну модель и одну сессию Nemotron через официальный C API `nemo_speech_diar_stream_*`, подаёт в неё последовательные PCM-буферы по 0,64 с и сохраняет состояние говорящих между буферами. ONNX-модель 3D-Speaker тоже загружается один раз; новый короткий embedding-stream создаётся только для анализа очередной реплики. Параметр `--pace realtime` ждёт поступления каждой порции звука по часам, поэтому 125-секундная запись воспроизводится примерно 125 секунд плюс загрузка и финальный сброс.

На уже настроенной машине этого проекта команда PowerShell выглядит так:

```powershell
$project = 'C:\Users\Ефим\OneDrive\Документы\ChatGPT\AI референт'
$runtime = 'C:\Users\Public\NemotronTest'
& "$runtime\speaker-verify-venv\Scripts\python.exe" "$project\stt-module\server-prototype\stream_replay.py" `
  --audio "$project\diarization-test\ru_interview_dialogue_125s.wav" `
  --nemo-lib "$runtime\runtime\bin\nemo_speech_asr_c.dll" `
  --nemo-model "$runtime\model.gguf" `
  --speaker-model "$runtime\speaker_embedding_model.onnx" `
  --output-dir "$project\diarization-test\stream-replay-my-run" `
  --chunk-seconds 0.64 --pace realtime --save-chunks
```

Программа печатает по одной JSON-строке для каждого буфера и одновременно пишет их в `events.jsonl`. В каждой строке есть интервал поданного аудио, прошедшее время, длительность вычислений, отставание от темпа записи, предварительно активный говорящий и завершённые реплики. Последние два файла: `segments.json` — объединённые реплики, `summary.json` — итоговые задержки и числа ролей. `--save-chunks` дополнительно сохраняет физические WAV-фрагменты в `chunks/`; для самой подачи модели эти файлы не нужны. Для быстрого теста без ожидания используйте `--pace fast`.

Эталон по-прежнему берётся из окна 20–30 с **до** начала воспроизведения файла. Это допущение теста: в настоящем интервью кнопка записи эталона должна дать такой голосовой образец раньше, чем система сможет подписывать реплики кандидата. Предварительная метка активного голоса может измениться; законченные реплики записываются отдельно. Логи содержат роли говорящих, а не слова: STT пока не подключена. Измерение скорости и совпадение с прежним прогоном не доказывают точность ролей на русских интервью.

Проверка 15.10.2026 на 125-секундном русском фрагменте, CPU AMD Ryzen 5 5600H: 196 буферов; суммарные вычисления 45,20 с, воспроизведение с ожиданием 126,02 с без времени подготовки. Максимальное отставание от темпа записи — 0,626 с. Медианная задержка публикации завершённого речевого интервала после его конца — 1,775 с, p95 — 2,553 с. Получены 13 интервалов «Кандидат», 8 «Интервьюер 1» и один эталон; их границы и роли совпали с прежним файловым прогоном на этой записи. Предварительные метки активного голоса совпали с финальными в 154 из 156 сопоставимых обновлений; 2 ранних обновления были исправлены после завершения реплики. Это сравнение двух результатов модели, не оценка точности по истинным ролям.
